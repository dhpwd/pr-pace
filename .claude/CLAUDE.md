# pr-velocity

A Node CLI that measures PR velocity from local git history – PR count, lines changed, a combined score and revert rate per person over time. It scans one repo or a folder of repos and writes JSON (`scan`) or a self-contained HTML report (`report`).

## Constraints

<!-- Only what changes engineering decisions in this repo, stated as rules, not narrative. Never replace a constraint with a link: sessions must be self-sufficient in the repo. -->

- The repo is going public. Keep personal details, private repo names and real data out of code, tests, fixtures and docs. Fixtures are generated by the tests, never copied from real repos
- Node 20 or later, ES modules, no runtime dependencies – Node built-ins only (`node:child_process`, `node:fs`, `parseArgs` from `node:util`)
- Git process budget per repo: one `git log --first-parent --diff-merges=first-parent --numstat -M` call, one batched call for second-parent authors and one `git check-attr --stdin`. Never spawn a process per commit
- Read-only against scanned repos – `--fetch` is the only option that writes to them
- The HTML report is one file: embedded scan JSON, inline SVG charts, vanilla JS, no external requests. It must work offline and as a message attachment
- The spec's design decisions define what the numbers mean (unit of work, first-parent walk, line exclusions, √lines score, revert handling). Raise a change to any of them as a design decision before implementing it
