# pr-pace

A Node CLI that measures PR pace from local git history – a one-line PR pace to post, and PR count, size-weighted PRs, median PR size, lines changed and revert rate per person over time. It scans one repo or a folder of repos and prints the PR pace line (`pace`) or writes JSON (`scan`) or a self-contained HTML report (`report`).

## Constraints

<!-- Only what changes engineering decisions in this repo, stated as rules, not narrative. Never replace a constraint with a link: sessions must be self-sufficient in the repo. -->

- The repo is public. Keep personal details, private repo names and real data out of code, tests, fixtures and docs. Fixtures are generated by the tests, never copied from real repos
- Node 22 or later, ES modules, no runtime dependencies – Node built-ins only (`node:child_process`, `node:fs`, `parseArgs` from `node:util`). Use no API added after Node 22.0 – `npm run typecheck` checks against the newest 22.x types, so it doesn't catch one. Keep the floor at 22 past its end of life: from 1.0.0, raising it is a major version, which changes the version on every posted PR pace line
- Git process budget per repo: the per-commit work is one `git log --first-parent --diff-merges=first-parent --numstat -M` call, one batched call for second-parent authors and messages, one `git check-attr --stdin` and one batched `git check-mailmap` for co-author identities. A fixed number of setup calls sits outside it – `git config user.email`, default-branch resolution, `git check-mailmap` for the author filter, `git remote get-url origin` (only when a PR credits a person's no-reply address the filter misses) and `git fetch` under `--fetch`. Never spawn a process per commit or PR
- Read-only against scanned repos – `--fetch` is the only option that writes to them
- The HTML report is one file: embedded scan JSON, inline SVG charts, vanilla JS, no external requests. It must work offline and as a message attachment
- The spec's design decisions define what the numbers mean (unit of work, first-parent walk, PR attribution (who a PR counts for), line exclusions, size-weighted PRs, median PR size, revert handling, the PR pace figure and its 30-day window). Raise a change to any of them as a design decision before implementing it
- The PR pace line carries the package's major version. A change to the figure's definition – weighting, window, which PRs count, line exclusions – needs a major version bump

## Commands

- `npm test` – run the unit tests
- `npm run typecheck` – `tsc --noEmit` over the source and tests
- `npx . pace <path>` / `npx . scan <path>` / `npx . report <path>` – run the CLI from the checkout. Bare `npx pr-pace` falls through to the npm registry, and `npm link` leaves a global symlink behind
