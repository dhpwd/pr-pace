# pr-velocity – v1 spec

A command-line tool that measures PR velocity from git history: how many pull requests a person lands, how big they are and how often they get reverted, over time. It runs against one repo or a folder of repos and produces JSON and an interactive HTML report.

## Scope

**In v1**

- Merged pull requests on each repo's default branch, read from local git history
- Squash-merged and merge-commit PRs (GitHub and GitLab conventions)
- Three volume metrics (PR count, lines changed, combined score) and one quality check (revert rate)
- Filtering and breakdown by author, with `.mailmap` support
- `scan` (JSON) and `report` (self-contained HTML)

**Out of scope for v1**

- **Commits pushed straight to the default branch.** Commit frequency is personal habit, so commit counts aren't comparable between people. A possible later option: treat each day's direct commits as one PR-equivalent, comparable only with your own history
- **Rebase-merged PRs.** "Rebase and merge" lands each branch commit separately with no PR number, so local history can't group them. A later `--source github` option would read PRs from the GitHub API instead. That option would also handle organisation-wide runs without cloning, but it needs a token, works only with GitHub and can't apply the file exclusions in [Lines changed](#lines-changed)
- Bitbucket and other hosts' merge conventions

## Design decisions

These define what the numbers mean, so they're recorded here with the reason.

- **PRs, not commits, are the unit of build work.** A PR is the reviewed, landed unit in most teams' build workflow. Repos with no PRs (a notes vault, a dotfiles repo) drop out, so the tool needs no rule for which repos hold code
- **First-parent history only.** `git log --first-parent <default branch>` gives one commit per landed PR under both squash and merge-commit flows, so the two are counted the same way. Commits on PR branches are never counted individually
- **Lines changed = added + removed.** This matches the "changes" figure GitHub shows on a PR, so anyone can check it. Net growth (added − removed) would penalise refactoring and deleting dead code. Renames are detected, so moving a file doesn't count as deleting and re-adding it
- **Docs, lockfiles and generated files are excluded from lines by default.** Agents produce markdown quickly and at length, and nobody writes lockfiles or build output by hand. Tests and config count. A docs-only PR still counts as a PR but scores zero
- **Combined score = √lines per PR, summed.** Summing raw lines per PR is just total lines, so the PR count would add nothing. The square root gives each PR weight by size while stopping one huge PR from dominating. Known trade-off: splitting a change into several PRs scores somewhat higher than landing it as one. Any weighting that grows more slowly than size does this, and linear weighting rewards padding instead. Small PRs are good practice, so this is the acceptable direction
- **Revert rate as the quality check.** Volume can rise while quality falls. The share of PRs later reverted is cheap to detect and needs no setup

## Commands

The binary is `pr-velocity`, runnable with `npx pr-velocity` (or `npx .` from a checkout). Every command has full `--help` text, and `pr-velocity --version` prints the version. Errors go to stderr, exit with status 1 and say what went wrong and what to do instead (e.g. "couldn't write out.json – check the folder exists"). Running with no command prints the help to stderr and exits with status 1. Repo warnings go to stderr as `pr-velocity: warning: <repo>: <message>`, so JSON on stdout stays clean, and are kept in the repo's `warnings` in the JSON.

### `pr-velocity scan [path...]`

Writes the scan result as JSON to stdout, or to `--out <file>`.

| Option                              | Default                            | Effect                                                                                                                                                                  |
| ----------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `path...`                           | `.`                                | Each path is a repo, or a folder whose subfolders are repos                                                                                                             |
| `--depth <n>`                       | `1`                                | How many folder levels below a path to look for repos                                                                                                                   |
| `--fetch`                           | off                                | Run `git fetch --all` in each repo first, so `origin/*` and a `--branch` on any remote are current                                                                      |
| `--branch <name>`                   | detected                           | Override the default branch for every repo                                                                                                                              |
| `--author <email\|name>`            | the repo's `git config user.email` | Count only this author (exact match, ignoring case, after `.mailmap`). Repeatable. Can't be combined with `--all-authors`                                               |
| `--all-authors`                     | off                                | Count every author (for team breakdowns)                                                                                                                                |
| `--since <date>` / `--until <date>` | all history                        | Limit by merge date. Each takes `YYYY-MM-DD` (in the scan's timezone) or a full ISO 8601 timestamp with an offset or `Z`. A bare `--until` date includes that whole day |
| `--include-docs`                    | off                                | Count docs files in lines changed                                                                                                                                       |
| `--exclude <glob>`                  | none                               | Extra paths to leave out of lines changed. Repeatable                                                                                                                   |
| `--out <file>`                      | stdout                             | Write JSON to a file                                                                                                                                                    |

A `--since` or `--until` value in any other form is an error naming the accepted formats, as is a `--since` later than `--until`.

### `pr-velocity report [path...]`

Runs a scan with the same options and writes the HTML report.

| Option               | Default            | Effect                                                                                              |
| -------------------- | ------------------ | --------------------------------------------------------------------------------------------------- |
| `--from <scan.json>` | –                  | Build the report from a saved scan instead of scanning. Paths and scan options with it are an error |
| `--out <file>`       | `pr-velocity.html` | Where to write the report                                                                           |
| `--open`             | off                | Open the report in the default browser                                                              |

## Behaviour

### Finding repos

- A path containing `.git` (directory or file) is a repo. Otherwise, search its subfolders down to `--depth`. A repo's own subfolders aren't searched
- Skip `node_modules` and dot-folders when searching
- A path that isn't a folder, or one whose search finds no repos, is an error naming that path
- A repo's `name` is its folder name. Where scanned repos share a folder name, each takes as many parent folders as it needs to be told apart (`work/x/app`, `oss/x/app`)
- If the same commit SHA appears in two scanned repos (e.g. two clones), count it once: the first repo in scan order keeps it, and the later repo gets a warning saying how many PRs were already counted under which repo. Where only the later repo holds the revert of a kept PR, the kept PR still takes its `reverted_by`

### Default branch

In order: the target of `refs/remotes/origin/HEAD`, then `origin/main`, then `origin/master`, then local `main`, then local `master`. Remote-tracking branches come first so the result reflects what has landed rather than local work. A repo with none of these is reported as a warning and skipped (it stays in `repos` with `branch: null`). `--branch` names a ref used as given in every repo, and a repo without it is skipped with a warning. A repo git can't read at all (a worktree whose main repo was deleted, an empty `.git` folder, a repo git refuses as dubiously owned) is skipped with git's own error rather than a `--branch` hint.

### Detecting PRs

Walk the default branch with `--first-parent`. For each commit:

| Pattern                                                                                                                  | Method   | PR number | Author                                       | Diff                                                      |
| ------------------------------------------------------------------------------------------------------------------------ | -------- | --------- | -------------------------------------------- | --------------------------------------------------------- |
| Two or more parents, subject `Merge pull request #N from …` (GitHub) or body containing `See merge request …!N` (GitLab) | `merge`  | N         | Author of the second parent (the branch tip) | First parent → merge commit                               |
| Two or more parents, subject ending `(#N)` (GitHub's "Pull request title" merge-commit message setting)                  | `merge`  | N         | Author of the second parent (the branch tip) | First parent → merge commit                               |
| One parent, subject ending `(#N)`                                                                                        | `squash` | N         | Commit author                                | Parent → commit                                           |
| Anything else                                                                                                            | –        | –         | –                                            | Not counted. Tallied per repo as `direct_commits_ignored` |

- The subject is the message's first paragraph, as git defines it
- `title` is the subject with any trailing `(#N)` suffix stripped. For a `Merge pull request #N from …` commit, `title` is the first non-empty line of the commit body (GitHub puts the PR title there), falling back to the subject when the body is empty. A GitLab merge keeps its subject as the title
- Merge time is the commit's committer date
- Author identities go through `.mailmap` (use `%aN` / `%aE`)
- The default author filter matches the email from `git config user.email` as seen from each repo, so per-repo config is respected. That email, and each email-shaped `--author` value, goes through the repo's `.mailmap` (`git check-mailmap`) so the filter matches the mapped identities. A `--author` value in the form `Name <email>`, with or without the `(count)` the no-match warning below adds, matches by its email. A value without `@` matches the mapped author name
- A repo with no `user.email` configured counts no PRs under the default filter and gets a warning to pass `--author` or `--all-authors`
- If a repo has PRs in the date range but none match the author filter, add a warning to that repo naming the five most frequent PR authors found (`Name <email> (count)`), with a hint to pass `--author`. This catches a local git email that differs from the one GitHub records on squash merges

### Lines changed

Per PR, from `git diff --numstat -M` over the diff in the table above:

- Binary files (numstat `-`) are ignored
- Excluded by default:
  - docs: `*.md`, `*.mdx`, `*.markdown`, `*.rst`, `*.adoc`, `*.txt` (extensions matched ignoring case). A `.txt` file still counts when it is config: a name containing `requirements` or `constraints`, any `.txt` under a `requirements/` folder at any depth, `CMakeLists.txt` and `robots.txt` (matched ignoring case). Build output, linguist attributes and `--exclude` globs still exclude them
  - lockfiles: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lock`, `bun.lockb`, `Cargo.lock`, `poetry.lock`, `uv.lock`, `Gemfile.lock`, `composer.lock`, `go.sum`
  - build output: `*.min.js`, `*.min.css`, `*.map`, and anything under a `dist/`, `build/`, `vendor/` or `node_modules/` folder at any depth
  - anything the repo's `.gitattributes` marks `linguist-generated`, `linguist-vendored` or `linguist-documentation` (set or `=true`), read from the default branch's tip with `git check-attr --stdin --source=<branch>` in one batch per repo. `--source` needs git 2.40 or later. Without it the repo gets a warning and the linguist exclusions are skipped
- `--include-docs` drops the docs extension list only. Files marked `linguist-documentation` stay excluded
- `--exclude` adds globs: `*` matches within a folder, `**` across folders, `?` one character, everything else is literal. As in `.gitignore`, a glob without `/` matches a file or folder name at any depth (`*.snap`, `fixtures`), a leading or inner `/` anchors it at the repo root, where it matches a path or any folder above it (`/api`, `src/gen`, `src/**/*.gen.ts`), and a trailing `/` alone doesn't anchor (`build/` matches at any depth)
- `lines = added + removed` over the files kept. Lines in excluded files are reported separately as `excluded_lines`
- `score = √lines`, rounded to two decimals

### Reverts

- A PR is a revert if its title starts `Revert "`, or its message contains `This reverts commit <sha>` where `<sha>` (full or a prefix of at least seven characters) is an earlier PR commit in the repo's first-parent history. A `This reverts commit` line naming any other SHA is ignored: a squash PR's body carries every branch commit's message, so a branch commit that reverted another branch commit would otherwise make an ordinary PR count as a revert
- Link a revert to the original PR by the first such SHA. Otherwise, take the quoted text from `Revert "…"` in the title, strip any `(#N)` suffix and match it against an earlier PR's raw subject or its title (each with any `(#N)` suffix stripped), taking the most recent match. A revert with no match still counts as a revert, unlinked
- Detection and linking run over the full first-parent history, before the author filter and before `--since`/`--until`. So another author's revert still marks your PR, a PR in range reverted after `--until` keeps its `reverted_by` and a revert whose original predates `--since` still counts as a revert
- A direct commit (not a PR) whose message contains `This reverts commit <sha>` naming an earlier PR commit also marks that PR as reverted. This is how `git revert` pushed straight to the default branch shows up. The direct commit is linked by SHA only, never by its title, and stays uncounted like any direct commit
- Revert PRs are left out of PR count, lines and score. Reverting isn't progress
- The original PR is marked `reverted_by` (the first revert's SHA, whether a revert PR's or a direct commit's – PR numbers aren't unique across repos) and counts towards the revert rate of the period it was merged in
- Recent periods will understate the revert rate because their PRs have had less time to be reverted. The report says so beside the metric

### Repo warnings

A repo's warnings say what happened and what to do. Besides those above (no default branch, `--branch` not found, a repo git can't read, no `user.email`, no PRs matching the author filter, PRs already counted under another repo, linguist attributes unreadable), a failed `git fetch` scans the local copy as it is and a failed `git log` skips the repo. That includes a log too large for Node to hold as one string (about 512M characters). An unreadable set of merge PRs' branch commits falls back to the merge commits' authors. A skipped repo carries only the reason it was skipped.

### Periods

- Bucket by merge time in the scan's timezone (`options.timezone`), in the CLI and in the report alike, so every reader of a report sees the same buckets whatever their own zone
- Weeks start on Monday (ISO weeks)

## JSON output

```json
{
  "generated_at": "2026-10-17T21:00:00+01:00",
  "options": {
    "authors": ["…"],
    "all_authors": false,
    "include_docs": false,
    "exclude": [],
    "since": null,
    "until": null,
    "timezone": "Europe/London"
  },
  "repos": [
    {
      "name": "my-app",
      "path": "/home/me/code/my-app",
      "branch": "origin/main",
      "prs": 42,
      "direct_commits_ignored": 17,
      "warnings": []
    }
  ],
  "prs": [
    {
      "repo": "my-app",
      "sha": "…",
      "number": 35,
      "title": "Add retry with backoff to the export job",
      "method": "squash",
      "author_name": "…",
      "author_email": "…",
      "merged_at": "2026-10-14T10:12:00+01:00",
      "added": 120,
      "removed": 34,
      "lines": 154,
      "excluded_lines": 12,
      "score": 12.41,
      "is_revert": false,
      "reverted_by": null
    }
  ]
}
```

- `options.timezone` is the scanning machine's IANA zone (`Intl.DateTimeFormat().resolvedOptions().timeZone`). `generated_at` and `merged_at` carry that zone's offset, to the second
- `options.authors` lists the `--author` values as given. Without `--author` or `--all-authors`, it lists the distinct default emails used (each repo's `git config user.email` after `.mailmap`). It's an empty list when `all_authors` is true, and the report offers split-by-author only then
- `options.exclude` lists the `--exclude` globs as given, or `[]`
- `options.since` and `options.until` hold the values as given, or `null`
- `repos[].prs` counts the PRs that pass the author and date filters – the same set as that repo's rows in `prs`, revert PRs included
- `repos[].direct_commits_ignored` counts the first-parent commits that aren't PRs, under the same author and date filters
- `prs` holds every PR that passes the filters, revert PRs included (`is_revert: true`), so a reader can trace them. `added` and `removed` cover the files kept. Rows are sorted by `merged_at`

## HTML report

The report is one self-contained file. It embeds the scan JSON, leaving out each repo's `path` and `warnings`: the report shows neither, and both can carry local folder names into a file that gets sent around. It makes no external requests (its tab icon is a `data:` URI) and draws its charts as inline SVG with vanilla JS, so it works offline and when attached to a message.

**Controls**

- Date range: presets (last 30 days, 90 days, 12 months, all) plus custom from/to. Presets count back from `generated_at`, not from when the page is opened, so an attached report shows the same numbers whenever it's read. Like the periods, they work in days in `options.timezone`: 30 and 90 days end on `generated_at`'s day and include it, and 12 months runs from the day after the same date a year earlier. "All" runs from `--since` (or the earliest PR) to `--until` (or `generated_at`'s day). A remembered custom range that holds none of this report's days falls back to 12 months
- Period: day, week, month
- Metric: PRs, lines changed, score, revert rate
- Split: none, by repo, by author (author only when the scan used `--all-authors`)
- Repo filter: checkbox per repo, with all/none

**Display**

- A header line giving when the scan ran, how many repos it covered, the authors counted, the timezone and what lines changed leave out, naming any `--exclude` globs in quotes. With no authors to count, it says whether no repo could be scanned or no scanned repo had `user.email` set
- Summary row for the selected range: PRs, lines, score, revert rate, each with the change against the previous range of equal length. "All" has no previous range, so it shows no change figures, and nor does a range whose previous range starts before `--since`. The revert-rate tile always carries the note that recent PRs have had less time to be reverted
- Bar chart of the selected metric per period, stacked when split, with a 4-period moving average line over the total. Revert rate with a split draws side-by-side bars per series (rates don't stack), and its moving average pools the four periods (reverted ÷ PRs across them)
- Series colours follow the entity, not the filter: up to eight repos or authors get a hue each, ranked by PR count over the whole scan. Past eight, the top seven do and the rest share "Other"
- Tooltip on hover or keyboard focus with the period's values per series
- Clicking a bar lists that period's counted PRs (merge date, repo, number, title, author when split by author is available, lines, score) so any number can be traced to its PRs. Reverted PRs are marked. For PRs, lines and score the listed rows sum to the bar within display rounding. For revert rate, reverted ÷ listed equals the bar. Under a split, the list covers every series in the period, and its summary gives each series' reverted ÷ PRs, matching that series' bar. Revert PRs merged in the period are noted, not listed. Selecting a bar by keyboard keeps focus on it
- Light and dark themes following the system setting
- Usable at phone width

Selected controls are remembered in `localStorage` for each set of scanned repo names, with the page working normally if storage is unavailable. Reports opened from disk share one storage origin, so a report on the same repo names picks up the controls and one on other repos starts from the defaults.

## Implementation constraints

- Node 20 or later, ES modules, no runtime dependencies (`node:child_process`, `node:fs` and `parseArgs` from `node:util`). `npm run typecheck` (`tsc --noEmit` with `checkJs`, `strict` and `@types/node` 20.x) catches most APIs newer than Node 20, but not all: `path.matchesGlob` is in the 20.x types because Node 20.17 has it, while 20.0–20.16 don't – hence the hand-written glob matcher
- Per-commit work is one `git log` call per repo for commits and numstat (`--first-parent --diff-merges=first-parent --numstat -M`), plus one batched call for second-parent authors and one `git check-attr --stdin`. A fixed number of setup calls per repo sits outside that budget: `git config user.email`, default-branch resolution, `git check-mailmap` and `git fetch` under `--fetch`. Never a process per commit
- Read-only against scanned repos, apart from `--fetch`
- Each scanned repo is found from its own folder. Git runs without the variables that tie it to one repo (`git rev-parse --local-env-vars` less its config variables, so config set through the environment still applies), and with `GIT_CEILING_DIRECTORIES` at the repo's parent, so a broken `.git` folder inside another repo fails rather than reading the outer repo. The technique and why: `docs/patterns/git.md`
- The report's browser code is inlined from `src/time.js` and `src/report/client.js` with `Function.prototype.toString`, so every export of those modules is a function declaration that uses only browser globals, its own locals and other inlined exports. The technique and its pitfalls: `docs/patterns/report-inlining.md`
- The repo will be made public. Keep personal details, private repo names and real data out of code, tests, fixtures and docs. Fixtures are generated, never copied from real repos

## Verification

- **Unit tests** (`npm test`) build throwaway fixture repos in a temp folder, with every git call run under `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`, without the variables that tie git to one repo and with explicit identities, covering:
  - a squash-merged PR
  - a merge-commit PR whose branch commits must not be counted
  - a merge-method PR whose `title` comes from the body's first line
  - a two-parent merge commit with subject `Title (#N)` (counted as `merge`)
  - a direct commit to the default branch (not counted)
  - a rename with a small edit (counts only the edit)
  - a PR touching a lockfile and a markdown file (both excluded, and the markdown counted under `--include-docs`)
  - a `.gitattributes` `linguist-generated` file (excluded)
  - a revert PR linked by SHA and one linked by subject
  - a squash PR whose body contains `This reverts commit <sha>` for a SHA not on the default branch (not a revert, counted normally)
  - a merge-method revert PR detected by its title and linked to the original merge PR
  - a `git revert` pushed straight to the default branch (marks the PR, not counted)
  - a revert by another author marking the filtered author's PR
  - reverts linked across `--since` and `--until`
  - a repo with no `origin/HEAD` (falls back correctly), and a repo git can't read
  - `--fetch` fetching every remote, and a repo with no remotes fetching without a warning
  - a broken `.git` folder inside another repo (skipped, not read as the outer repo)
  - an inherited `GIT_DIR` redirecting neither the scan nor the fixtures, and config passed through the environment still applying
  - a folder of repos at depth 1 and depth 2
  - two authors, with a `.mailmap` merging one author's two emails
  - `--author` matching regardless of case, and in the `Name <email>` forms the no-match warning lists
  - an author filter that matches no PRs (warning lists the authors found)
  - bucketing that gives the same periods whatever `TZ` the test process runs under
  - the start of a day where the clocks skip midnight
  - `--since`/`--until` formats, including an impossible date in a timestamp
  - `--exclude` glob matching and the default exclusions
  - config `.txt` files (`requirements-dev.txt`, `requirements/base.txt`, `CMakeLists.txt`, `robots.txt`) counted, prose `.txt` files (`notes.txt`, `LICENSE.txt`, `llms.txt`) excluded, and config `.txt` files under build output or matched by an `--exclude` glob still excluded
  - the CLI's help, errors, `scan --out` and `report --from`, and the package's `bin`, `engines` and lack of runtime dependencies
  - the report's figures (totals, per-series parts, moving averages, presets, series colours, remembered custom ranges, controls remembered per set of repos, axis ticks that never repeat a label), its header line and its embedded data block, without repos' paths and warnings
- **Typecheck:** `npm run typecheck`
- **Report check:** generate a report from fixture repos built as the tests build them, serve it over `http://127.0.0.1` (`python3 -m http.server --bind 127.0.0.1 <port>` from a scratch folder) and open it in a browser. Switch through each period, metric and split, click a bar and confirm the listed PRs add up to the bar's value, and confirm the network log shows no request beyond the page itself
